不要调整整体架构，不要迁移 OSS，不要重做 loading。

问题定位：

当前 sksir.top 首屏加载分为两个阶段：

1. 浏览器首次启动（冷启动）：

* 浏览器标签显示正在加载
* 页面黑屏约 0.2～0.5 秒
* 然后才出现网站自己的 loading 过渡

2. 页面资源加载完成后：

* CSS、JS、字体、图片都很快
* 缓存命中后刷新基本秒开

通过 HAR 分析：

* HTML、CSS、JS、字体请求时间都在几百毫秒以内
* 资源加载不是主要问题
* 问题发生在首次绘制（First Paint）之前

当前可能流程：

浏览器打开页面
↓
加载 index.html
↓
加载 style.css
↓
CSS 生效
↓
html 添加 is-booting
↓
显示启动遮罩
↓
JS 初始化
↓
添加 is-first-screen-ready
↓
隐藏启动遮罩
↓
进入完整页面

现在的问题：

is-booting 启动状态依赖外部 CSS 和 JS 生效。

浏览器第一次打开时：

CSS 还没加载完成之前：

* 启动遮罩不存在
* loading 不存在
* 页面没有视觉反馈

所以用户看到黑屏。

重点检查位置：

1. index.html

目前存在类似：

document.documentElement.classList.add("is-booting");

这个逻辑不要删除。

但是需要保证浏览器解析 HTML 后马上有基础视觉反馈。

2. style.css

存在：

html.is-booting::before,
html.is-booting::after

类似启动遮罩逻辑。

例如：

html.is-booting::before {
    position: fixed;
    inset: 0;
    z-index: 999998;
}
html.is-booting::after {
    z-index: 999999;
}

问题：

这些 CSS 在 style.css 加载后才存在。

首次打开时存在时间差。

修改目标：

不要让整个首屏等待 CSS。

方案：

把启动遮罩最小必要 CSS 内联到 index.html。

例如：

<head>
<style>
html.is-booting::before {
    content: "";
    position: fixed;
    inset: 0;
    background: #111;
    z-index: 999998;
}
html.is-booting::after {
    content: "";
    position: fixed;
    left: 50%;
    top: 50%;
    width: 30px;
    height: 30px;
    border-radius: 50%;
    border: 3px solid rgba(255,255,255,.2);
    border-top-color: white;
    animation: boot-spin .8s linear infinite;
    transform: translate(-50%, -50%);
    z-index: 999999;
}
@keyframes boot-spin {
    to {
        transform: translate(-50%, -50%) rotate(360deg);
    }
}
</style>
</head>

作用：

浏览器解析 HTML 时：

立即知道：

* 背景颜色
* loading位置
* 转圈动画

不会出现黑屏等待。

完整 style.css 保持不变：

<link rel="stylesheet" href="style.css">

继续覆盖正式样式。

⸻

第二个优化点：

检查启动完成条件。

寻找：

is-first-screen-ready

或者：

classList.remove("is-booting")

类似：

document.documentElement.classList.remove("is-booting");

检查它前面是否等待：

await checkVersion();
await loadSites();
await loadBookmarks();
await loadBackground();
await loadFavicon();

如果存在：

不要让这些影响首屏。

改成：

showFirstScreen();
requestIdleCallback(() => {
    checkVersion();
    loadBookmarks();
    loadFavicon();
});

原则：

首屏只等待：

HTML结构
+
基础导航
+
主题配置

不要等待：

版本检测
favicon
背景高清图
快捷功能
设置模块
统计

⸻

第三个优化点：

app-version.json 不要阻塞首屏。

目前：

app-version.json?t=时间戳

因为带时间戳，不走缓存。

如果版本检测参与启动流程：

会增加固定等待。

改：

错误：

await checkVersion();
showPage();

正确：

showPage();
setTimeout(() => {
    checkVersion();
}, 1000);

⸻

最终目标：

打开浏览器：

现在：

黑屏
 ↓
等待
 ↓
loading
 ↓
页面

优化后：

立即出现启动背景/loading
 ↓
页面初始化
 ↓
淡出loading
 ↓
完整页面

不要追求取消 loading。

目标是：

让 loading 从“等待后出现”变成“立即出现”。

⸻

不要修改：

* Vercel 部署
* OSS资源位置
* CSS/JS架构
* 版本号缓存方案

目前资源加载速度已经正常，重点优化首次绘制体验。
